`SupersededSummaryPruneReceiptSchema` = `{ operation, personId, prunedSummaryIds, deletedVectorRows,

`SqliteStore.commitSupersededSummaryPrune` (`src/storage/sqlite-store.ts:1183-1276`): `begin immediate`
/ `commit` / `rollback` by hand, loads reference sets once, decides every skip before any write, deletes
with inline `prepare("delete from ... where id = ?")` statements (never `deleteIds(...)`, which opens its
own transaction and would nest), parses the receipt through its schema before committing.
`InMemoryStore.commitSupersededSummaryPrune` (`src/storage/in-memory-store.ts:847-919`): same decision
order, mutates its arrays only after every decision is made, `structuredClone`s the parsed receipt.

Existing anchor surface (`src/storage/memory-store.ts:188-190`):
```ts
saveAnchor(anchor: Anchor): Promise<void>;
listAnchors(): Promise<Anchor[]>;     // NO personId parameter — loads every anchor
deleteAnchors(ids: string[]): Promise<void>;
```

`AnchorSchema` (`src/domain/types.ts:149-166`): `id`, `personId?`, `scopeId?`, `canonicalEventId?`,
`turnId`, `threadId`, `boxId`, `anchorType`, `content`, `embedding`, `createdAt`, `trustLevel`, `source`.
Anchors are stored as `anchors (id text primary key, payload text not null)` — no person column, no
index, and there is no `anchor_vectors` table (an anchor's embedding lives in its own payload).

The classifier (`src/topic/derivation-hygiene.ts`):
```ts

export const classifyEvent: (event: ClassifiableEvent) => ClassificationResult;  // .derivationClass
```

Read-only live-corpus facts measured 2026-07-27 (do not re-measure to plan; re-measure only as evidence):
all 45,911 anchors carry `personId: "aaron"` AND a non-null `canonicalEventId`; 8,911 have content
starting `[Tool call: `. So person attribution and event enrichment are both available in practice —
but the schema makes both optional, so the code must still handle their absence.

Fetching a canonical event by id in SqliteStore: `select payload from canonical_events where id = ?`
(the shape already used at `src/storage/sqlite-store.ts:1103`). In InMemoryStore the array is
`this.canonicalEvents` (`src/storage/in-memory-store.ts:141`).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller id list → store transaction | An id list is untrusted input; only the in-transaction recompute may authorize a delete |
| anchor row → person isolation | `Anchor.personId` is optional, so ownership can be unknown and must not default to the requester |
| classifier → deletion | A classification bug deletes real conversational memory irreversibly |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-60 | Elevation of Privilege | `commitUnhygienicAnchorPrune` trusting `anchorIds` | mitigate | Eligibility recomputed in-transaction; case (d) asserts a conversational id in the caller list is still retained |
| T-11-61 | Information Disclosure | An anchor with no `personId` deleted under another person's request | mitigate | `person_unattributed` skip reason; case (f) asserts the row survives |
| T-11-62 | Tampering | Deleting conversational memory through an over-broad classifier | mitigate | The single shipped `classifyEvent` predicate, no new rules; conservative-by-default (unmatched stays conversational); cases (c)/(g) pin both directions |
| T-11-63 | Tampering | The prune reaching other entities (summaries, turns, canonical events) | mitigate | Inline `delete from anchors` only; case (j) asserts before/after control-count equality across seven tables |
| T-11-64 | Denial of Service | An unbounded page or a wedged cursor on a 45,911-row table | mitigate | `anchorIds` capped at 1000 by schema; primary-key cursor advances past skips |
| T-11-65 | Repudiation | A store-parity drift where SqliteStore and InMemoryStore disagree | mitigate | One `describe.each` body run against both stores, not two hand-kept suites |
| T-11-SC | Tampering | npm/pip/cargo installs | accept | No packages installed in this plan |
