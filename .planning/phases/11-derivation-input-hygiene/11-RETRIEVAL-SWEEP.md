## Residual risk

- **`ConversationResumer` (`resumeSummary`/`resumeTrace`/`resumeBox`) performs no person/scope
  authorization at all.** This is a pre-existing gap, orthogonal to GAP-11-A (it is a missing
  identity/scope boundary, not a missing state boundary) and out of this plan's declared file
  scope (`src/resume/conversation-resumer.ts` is not in this plan's `files_modified`). It is
  surfaced here for visibility rather than silently left out of the sweep. Recommend a follow-up
  gap or Phase-11-adjacent plan if resume is meant to be authority-scoped like the MCP tools.
- **Proposal/review-facing candidate pools (`sleep-reviewer.ts`, `proposal-scheduler.ts`) use
  `state !== "superseded"`, not the centralized `isRetrievableState` allow-list.** This is
  intentional — `stale` summaries must remain eligible for proposal generation — but it means a
  future addition to `MemoryStateSchema` would need updating at each of these blacklist sites
  individually, unlike the allow-list sites (`memory-query-service.ts`, `subject-expansion-service.ts`,
  `findNearestSummaries`, `applyRetrievalBoundary`) which fail closed automatically. Accepted
  because changing these to an allow-list is a proposal/review-contract change, explicitly out of
  this phase's scope fence.
- **`backfill-embeddings-command.ts` embeds every summary regardless of state**, including
  summaries that will never be retrievable. This spends embedding compute on content that will be
  filtered at query time by this plan's `findNearestSummaries` fix. Accepted: reducing that waste
  is vector/ANN-shaping work explicitly deferred to Phases 12-14 per the phase scope fence.
