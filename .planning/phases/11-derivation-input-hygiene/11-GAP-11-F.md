# GAP-11-F — A live credential escaped `secret-redactor.ts` and propagated into derived summaries

**Status:** open (detection gap) — **rotation DECLINED by owner 2026-07-27: credentials are old/stale**
**Found:** 2026-07-27 by the Plan 11-21 executor, scanning probe artifacts under T-11-72
**Severity:** higher than GAP-11-E. GAP-11-E leaks tool-call noise into agent context; this leaks
live credentials into agent context, into git, and into any future injection packet.

## What it is

A real credential pair for a `mission-control-jiye.onrender.com` service — a 64-hex API key and a
plaintext login (`aaron` / a real password) — is present **unredacted** in `~/.memory/aaron.db`:

| location | rows |
|---|---|
| `anchors` | 8 |
| `summaries` | 143 |

The credential entered as raw `[Tool call: execute_code]` content. Two separate controls failed:

1. **Import-time redaction missed it.** `src/imports/secret-redactor.ts` demonstrably works — other
   API keys in the same corpus are correctly stored as `[REDACTED]` (e.g. `apiKey: '[REDACTED]'`,
   observed in the `before-v2` probe artifact). This pair escaped it.
2. **The derivation pipeline propagated it.** The password survived out of the raw anchor and into
   **143 derived summaries**. Phase 11's hygiene classifier and the summarizer neither caught nor
   redacted it — unsurprising, since neither is a secret scanner, but it means one missed redaction at
   import fans out across the derived corpus.

Because these rows are retrievable, the credential can be selected into an injection packet and shown
to any agent host. It was in fact selected by the frozen probe: raw-anchor form for Q6
(`after-filter-v2`) and derived-summary form for Q9 (`current-v2`).

## Blast radius outside the database

- **Probe artifacts.** `11-probe-after-anchor-prune.json` (Plan 11-18) and the `probe-v2/`
  `after-filter-v2.{json,md}` / `current-v2.json` files (Plan 11-21) contained it verbatim.
  Both are now redacted in the working tree (`b9737e3`, `9f1742f`).
- **Git history.** The credential is present in **16 commits**, `00de5a3` through `9f1742f`. The
  earliest is Plan 11-18's, not Plan 11-21's — the exposure predates the plan that found it.
- **Not pushed.** `forgejo/main` is 375 commits behind; nothing has left this machine. History
  remediation is therefore possible without coordination cost, but spans 16 commits and would rewrite
  every SHA from `00de5a3` forward — including the SHAs cited throughout this phase's planning docs.

## Owner decisions

1. ~~**Rotate the credential.**~~ **Owner decision 2026-07-27: declined — the credentials are old and
   the service is not a live concern.** The owner is the authority on whether that account is active;
   recorded here rather than re-argued. Note for a later reader: the values remain in the corpus and in
   git history, so if that service is ever revived the credentials must be rotated first.
2. **Git history rewrite** — `git filter-repo` / `filter-branch` (interactive rebase is unavailable in
   this environment). Cheap in coordination terms since nothing is pushed; costs SHA stability.
3. **Corpus remediation** — 151 rows. Unlike GAP-11-D's anchors, summaries are referenceable, so a
   prune is not obviously the right shape; targeted redaction-in-place may be. Needs its own plan.

## The product defect — STILL OPEN regardless of the rotation decision

The owner's decision above concerns *this* credential's staleness. It does not resolve the underlying
defect: `secret-redactor.ts` missed a credential class, and one missed redaction at import fanned out
into 143 derived summaries. The next secret it misses may not be stale. Treat the two below as live
work items independent of the rotation call.

## The product defect, stated separately from the incident

Two distinct things to fix, and they should not be conflated:

- **Detection gap:** whatever pattern class this credential falls into is not covered by
  `secret-redactor.ts`. Determine what shape it is and why the existing rules missed it. Note the
  password is not a high-entropy token — it is a human-chosen password following a prose lead-in
  ("Your MC login: ..."), which is a genuinely harder detection problem than an API key and may be why
  it escaped.
- **Propagation:** one missed redaction at import became 143 contaminated summaries. Consider whether
  derivation should re-scan, or whether redaction must be authoritative at import and the pipeline is
  right to trust it. This is a design question, not a bug to patch reflexively.

## Not to be folded into GAP-11-E

GAP-11-E is about tool-call text reaching packets and is being investigated by Plan 11-22. This gap
shares a symptom (unwanted content in derived summaries) and nothing else: different root cause,
different severity, different remediation shape, and an owner action (rotation) that no code change
substitutes for. Track and plan it separately.
