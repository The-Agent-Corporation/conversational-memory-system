<objective>
Close GAP-11-F's DETECTION half: `src/imports/secret-redactor.ts` missed a credential and one missed
redaction at import fanned out into 143 derived summaries.

The owner declined rotating that particular credential on 2026-07-28 ("those are really old") and that
decision stands — this plan is NOT about that credential's staleness. It is about the next one, which may
not be stale. The redactor demonstrably works on other keys in the same corpus (`apiKey: '[REDACTED]'`
appears throughout); this class escaped it.

**The hard part is stated up front so it is not discovered mid-plan.** What escaped was not a
high-entropy token. It was a human-chosen password following a prose lead-in — roughly the shape
"Your MC login: <user> / <password>". That is a genuinely harder detection problem than an API key:
there is no entropy signature, no vendor prefix, and no fixed length. A naive rule here will either miss
it or redact legitimate prose. Both failure modes are worse than the status quo, and a plan that produces
a high-false-positive rule has made memory less useful, not safer.

Purpose: REQ-053.
Output: a targeted detection rule with measured precision on the real corpus, plus a recorded decision on
propagation.
</objective>
