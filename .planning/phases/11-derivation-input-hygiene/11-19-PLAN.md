<objective>
Make the recall probe measure what the phase's acceptance actually claims. Three defects were verified
against the code and the probe JSON on 2026-07-27:

1. The probe's harness detector is a hand-rolled 3-pattern subset (`[SYSTEM:`, `[cron:`, `[SILENT]`)
   of the 13 shipped `SYNTHETIC_RULES`. Demonstrated miss: Q7/Q8's `after-filter` top memories begin
   `### Task:` (rules `automated-task-block` / `automated-followup`) and were recorded as clean.
2. The probe reports one boolean per packet with no attribution. `packet.selectedMemory` IS the joined
   text of every selected memory (`memory-retriever.ts:76`), so the boolean does cover the whole packet
   — but nothing records WHICH memory or WHICH rank carries the offending text, and `sourceSummaryIds`
   is a packet-wide union (`memory-retriever.ts:77`), so it cannot establish that the offending item is
   summary-derived. GAP-11-E's central inference rests on exactly that union.
3. `<task-notification>` is not in `SYNTHETIC_RULES` at all — a product gap, fixed in Plan 11-20, not here.

Purpose: without per-item attribution, Stage D cannot tell a leaking rule from a stale summary, and the
GAP-11-E fix would be guesswork.
Output: a corrected probe harness, a marker export that stops probe/product drift, and a written record
of which historical numbers survive the correction.
</objective>
