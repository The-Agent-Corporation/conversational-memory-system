<objective>
`prepareInjection` calls `listSummaries()` per query, loading and Zod-parsing every summary row every
time — 135,366 rows pre-rebuild, which made eight probe queries exceed ten minutes and made full-corpus
recall verification impractical. That is the same O(all-rows)-per-query shape as the hotspots fixed before
v1.1. Push person and state filtering down into the store query behind a supporting index.

Purpose: unblocks W4 (Plan 11-13's before/after recall probes) and makes the state filter from Plan 11-08
cheap instead of an extra pass over every row.
Output: filtered `listSummaries`, schema migration 3, both store implementations, and a measurable
row-count acceptance test.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller-supplied filter values → SQL text | Filter values must never reach SQL as text |
| store-level filter → retrieval boundary | An optimization must not become the only place authority is enforced |
| schema migration → live 4.6 GB database | A migration runs against the owner's real corpus on next open |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-29 | Tampering | SQL injection through `personId` or a state value interpolated into the filtered query | mitigate | Placeholders only; placeholder count is the sole input-derived part of the SQL text; acceptance criterion forbids value concatenation |
| T-11-30 | Elevation of Privilege | Boundary enforcement drifting into the store filter, so a caller omitting the filter gets unfiltered results | mitigate | `applyRetrievalBoundary` re-applies all three predicates; `git diff` acceptance criterion forbids removing any condition |
| T-11-31 | Denial of Service | Full-corpus scan per query keeping recall verification impractical (the observed >10 min for 8 queries) | mitigate | Expression index `idx_summaries_person_state` + `EXPLAIN QUERY PLAN` assertion + row-count bound |
| T-11-32 | Tampering | A malformed migration corrupting the live corpus on next open | mitigate | Append-only `MIGRATIONS`; index-only DDL, no data rewrite; migration runner's existing single-transaction + audit-row contract; idempotent-reapply test |
| T-11-33 | Information Disclosure | Legacy unscoped path bypassing the state filter because it has no personId | mitigate | Legacy branch still passes `states: RETRIEVAL_CANDIDATE_STATES` |
| T-11-SC | Tampering | npm/pip/cargo installs | accept | No packages installed in this plan |
</threat_model>
