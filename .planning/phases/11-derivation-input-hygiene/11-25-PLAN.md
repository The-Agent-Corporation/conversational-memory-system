<objective>
Apply the authorized remediation to `~/.memory/aaron.db` — a long-running operation on a 4.6 GB corpus
that supersedes tens of thousands of summaries and tombstones their vectors.

If `11-REMEDIATION-DECISION.md` scoped this plan out (class R-C), it stops at Task 1 with a recorded
no-op. Nothing here runs unconditionally.

Two facts shape the safety design:
- `rebuild-derivations` has **no dry-run mode**. The blast radius must therefore be measured by rehearsing
  the full operation on an APFS clone and reporting the clone's receipt — an estimate is not acceptable
  for a destructive-by-supersession operation, and Plan 11-18 already found a preview that under-reported
  a blast radius by 851 rows (fixed in `b7ae28b`).
- ADR 0051 records that no `rebuild-anchors` command exists. A restore from backup is the only recovery
  path for anything this touches that is not regenerable.

Purpose: REQ-054 (resumable, idempotent, checkpointed rebuild).
Output: `11-REBUILD.md` with rehearsal numbers, backup evidence, the owner's authorization, and the receipt.
</objective>

Staleness trigger (`src/operations/rebuild-derivations-command.ts:100`):
  const isStale = checkpoint === null || checkpoint.processorVersion !== PROCESSOR_VERSION || parsed.force === true;
and `PROCESSOR_VERSION = "continuous-contraction/v1+" + HYGIENE_RULE_VERSION`. Plan 11-20 bumped the rule
version, so the live corpus is already stale by this predicate — `--force` should not be needed, and if it
IS needed, that is a finding to report before applying, not to paper over.

Receipt shape (`RebuildDerivationsCommandResult`): `rebuilt`, `personId`, `hygieneRuleVersion`,
`processorVersion`, `slices`, `processedEvents`, `summariesWritten`, `supersededSummaries`.

Properties the rehearsal must confirm on the clone, not assume:
- Resumability/idempotence — interrupt mid-run and resume; the run converges to the same receipt
  (T-11-16: never restart from zero on every invocation)
- Anchors — the rebuild's immediate stage creates anchors. Confirm on the clone whether it regenerates
  anchors for spans whose unhygienic anchors Plan 11-18 pruned, and whether conversational anchors are
  duplicated or upserted by stable id. Report the anchor count before and after.
- Superseded growth — the rebuild supersedes rather than deletes (ADR 0050), so the ~87,727 rows already
  superseded will be joined by the newly superseded set. Report the resulting counts and file size.

Live corpus state as of Plan 11-18: 292,407 canonical events, 50,551 active + 87,727 superseded summaries,
19,268 anchors, `pragma user_version` 3. Existing backups: `~/.memory/aaron.db.pre-phase11`
(4,962,574,336 bytes), `~/.memory/aaron.db.pre-anchor-prune` (5,031,448,576 bytes). Neither is a
substitute for a fresh one — both predate the current state.
