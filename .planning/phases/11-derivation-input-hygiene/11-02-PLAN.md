<objective>
Wire hygiene into `ContractionRunner.drainSlice` — the phase's highest-risk work. Tool-activity and
synthetic events stop driving `TopicMonitor` (this is what produces the 59% COUNT reduction), each span
gains an explicit raw-event window so provenance never shrinks, and the summarizer receives
hygiene-transformed content while `Turn` rows and `sourceCanonicalEventIds` stay canonical.

Purpose: REQ-052 + REQ-053's derivation half, and REQ-054's staleness gate. 11-MEASUREMENT's key
finding is that collapse alone moves volume 61% but count only 14% — an implementation that collapses
but still lets activity lines open their own span hits the volume target and MISSES the count target.
This plan makes the label gate the primary mechanism and tests both.
Output: A hygiene-aware contraction path with full-corpus-shaped integration tests.
</objective>

<decision_note>
11-CONTEXT decision 6 anticipated extending `ContractionCheckpoint` with pending-tool-run state so a run
straddling a slice boundary still collapses to one line. This plan reaches the SAME observable outcome
without a schema change, because summary content is recomputed positionally over the span's full window
from `allEvents` on every slice: a provisional summary written mid-run is re-emitted under the SAME
deterministic id on the next slice with the complete run collapsed. The straddle case is a REQUIRED test
(Task 1), not an assumption. The one durable-state correction that IS needed — resuming from the last
PROCESSED event rather than the last LABEL-DRIVING event — uses the existing
`processedThroughOrderKey.id`, so both `sqlite-store.ts` and `in-memory-store.ts` stay untouched.
If review prefers the literal `pendingToolRun` field, it is additive and can be added later without
changing the observable contract.
