The frozen probe harness, REUSED UNCHANGED — the query set is frozen and must NOT be edited, reordered,
or extended:
```
npx tsx .planning/phases/11-derivation-input-hygiene/11-recall-probe.ts \
  --db <path> --person <personId> --label <label> --out <basename>
```
It writes `<basename>.json` and `<basename>.md` (two files, not a directory) and prints a per-query and
total elapsed line to stderr. Against the live corpus the full 12-query set took ~8.7 minutes in the
`after-filter` run — budget for that, and do not shorten the set to save time.

The prune command (Plan 11-17):
```
npx tsx src/cli/bin.ts prune-unhygienic-anchors --db <path> --person <id>            # dry-run, default
npx tsx src/cli/bin.ts prune-unhygienic-anchors --db <path> --person <id> --apply \
  --confirm-backup <backup-path>
```

Live-corpus baseline measured read-only 2026-07-27 (`11-GAP-11-D.md`): 45,911 anchors, all with
`personId: "aaron"` and a canonical event id — conversational 20,119 (43.8%), synthetic_injected 16,881
(36.8%), tool_activity 8,911 (19.4%). Because Plan 11-16 enriches classification with the canonical
event's `role`/`eventKind` and this census was content-only, the real prune count may EXCEED 25,792.
That is expected; record the real number.

Backup already on disk: `~/.memory/aaron.db.pre-phase11`, 4,962,574,336 bytes, mtime 2026-07-26 19:26.
ADR 0050 forbids deleting it until the SC7 sign-off (Plan 11-14) records that recall is good.

Known side effect of the probe itself, pre-existing and not introduced here: `prepareInjection` writes
summary-access bookkeeping, persists injection packets, and can promote a stale summary to revived. The
probe run is therefore not read-only against the live database, and never was.
