# GAP-11-H — A trailing `[SILENT]` sentinel discards the real reasoning that precedes it

**Status:** open — fixed by Plan 11-28
**Found:** 2026-07-28 by the orchestrator, characterizing the 350 anchors for the owner's decision
**Severity:** moderate. It deletes genuine memory content rather than admitting scaffolding — the
opposite failure direction from GAP-11-D/E/G, and the reason "prune all 350" was the wrong answer.

## What it is

Plan 11-24 replaced anchored `startsWith` matching with line-anchored `matchesEmbedded` to close H-i
(scaffolding embedded mid-event was invisible). That fix is correct for block scaffolding — a
`<task-notification>` or `<system-reminder>` block occupying its own lines really is scaffolding wherever
it appears. It is wrong for `[SILENT]`, which is a *response sentinel*, not a block: it means "emit
nothing", and agents write it on a trailing line AFTER explaining their reasoning.

```
{ id: "silent-sentinel", test: (c) => matchesEmbedded(c, markerFor("silent-sentinel")), roles: ["assistant"] }
```

So an event like:

```
PID 89914 is not alive. Per decision rule A, respond silently so Hermes can handle
the completion report separately.

[SILENT]
```

classifies `synthetic_injected` and its text is excluded from derivation entirely. Under
`hygiene-rules/v1`'s anchored matching it classified `conversational` — correctly. The v3 fix regressed it.

## How it surfaced

Not by a probe query. It surfaced while characterizing the 350 anchors that classify `synthetic_injected`
under v3, to answer whether the owner should prune them. The 350 split:

| rule | count | shape |
|---|---:|---|
| `task-notification` | 329 | all 329 START with `<task-notification>` — unambiguous scaffolding |
| `harness-system` | 1 | `[System note: Your previous turn was interrupted…]` — scaffolding |
| `silent-sentinel` | **20** | **real agent reasoning with a trailing sentinel** |

Samples from the 20, verbatim from the live corpus:

- "Confirmed — the McCay email was already processed fully (including strong summary with urgency)…"
- "All 12 Roscoe verification tasks are currently `awaiting_owner` under Hermes — waiting on Aaron's
  decision. Backlog tasks aren't candidates per runbook."
- "Confirmed. The prior run at 23:01 (27 minutes ago) already delivered a detailed preflight blocker
  report with both remediation paths and recommended pausing the job."
- "PID 89914 is not alive. Per decision rule A, respond silently." (×12, near-duplicates)

The first three are exactly the operational memory the system exists to keep. Pruning all 350 would have
deleted them, which is why the owner's decision was **prune 330, keep the 20, and fix the rule.**

## Counted blast radius (live corpus, read-only, 2026-07-28)

Assistant-role canonical events containing a `[SILENT]` line:

| shape | count | after the fix |
|---|---:|---|
| pure sentinel — residue empty once sentinel lines are removed | **2,784** | stays `synthetic_injected` |
| trailing after real prose | **123** | becomes `conversational` |
| starts with the marker but has residue | **0** | the ambiguous case does not occur |

123 events of 292,407 change classification. The absence of the third shape is what makes the fix clean:
there is no case where a bare-sentinel prefix is followed by substance, so "residue is empty" separates
the two populations exactly.

## The fix, and its deliberate narrowness

`silent-sentinel` fires only when the content's substantive residue is empty once sentinel lines are
removed. `matchesEmbedded` itself is NOT changed — the other ten rules that use it are correct, and
widening this fix past one rule would re-open GAP-11-E. See Plan 11-28.

## Consequence: the corpus needs another rebuild

The 123 events are currently classified scaffolding, so the `hygiene-rules/v3` rebuild EXCLUDED their
text from summaries. Making them conversational means that content belongs in the derived corpus and only
a rebuild puts it back. The version bump to v4 marks every checkpoint stale, so the rebuild fires without
`--force`. That is Plan 11-29, not this gap.

## Why the review missed it

Plan 11-24 reasoned about whether line-anchored matching would catch MORE scaffolding — it does — and
verified that its two known H-i offenders were prose discussing a marker in a table cell, which remained
conversational. It did not ask whether any marker in the table is a TRAILING sentinel rather than a
LEADING block, which is a property of the marker's semantics, not of the matching strategy. The rule
table treats all 13 markers as one kind of thing; they are not.
