<objective>
The live rebuild left 87,727 superseded summaries holding pre-hygiene tool-call text — roughly 155 MB of
the database. Plans 11-08/11-09 make them unreachable; this plan makes them removable. Build the
store-layer half: one atomic, named `commit*` method with authoritative in-transaction eligibility, plus
the two cheap read methods the command in Plan 11-12 needs for its dry-run and its resume cursor.

**Prune, not archive — and why.** Superseded summaries are pure derivations. Every one of them is
reproducible from the canonical events that are, by D-1, still present and immutable, using the existing
`memory rebuild-derivations` command. An archive table would duplicate 155 MB, add a second surface to
keep person/scope-isolated, and preserve exactly the text REQ-053 says must not be derivable-from. The
recovery story is the backup plus re-derivation, not a shadow copy.

Purpose: REQ-053 (excluded content should not persist as a retrievable-shaped object) and REQ-054's
"no duplicated or orphaned summaries, vectors, or trace assignments" applied to the cleanup direction.
Output: contract, interface additions, both implementations, tests.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller-supplied summaryIds → irreversible row deletion | The caller's list is a request, not an authorization |
| prune transaction → derived object graph | Boxes, traces, proposals, and summary chains hold references that must not dangle |
| prune → canonical timeline | D-1: canonical events are immutable and out of reach of any derivation cleanup |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-34 | Tampering | A caller passing an active summary id and deleting live memory | mitigate | Eligibility recomputed inside the transaction; `not_superseded` and `person_mismatch` skips; test cases (c) and (d) |
| T-11-35 | Tampering | Dangling references after prune — a box/trace/proposal pointing at a deleted summary | mitigate | Four reference-kind checks refuse the prune; test case (b) parametrizes all four |
| T-11-36 | Tampering | Orphaned vector rows outliving their summary and resurfacing in semantic recall | mitigate | Vector rows deleted inline in the same transaction; case (a) asserts both rows gone |
| T-11-37 | Tampering | Partial deletion on crash leaving summaries gone but vectors present | mitigate | Single `begin immediate` with rollback; fault boundaries between stages; atomicity case (e) asserts three unchanged counts |
| T-11-38 | Elevation of Privilege | Pruning another person's derivations | mitigate | `personId` bound in the contract and rechecked per row inside the transaction |
| T-11-39 | Tampering | Canonical events or turns deleted as collateral | mitigate | No delete statement against those tables; grep acceptance criterion asserts absence |
| T-11-40 | Repudiation | A prune replicating to other devices and destroying their derivations | accept | Summaries have no `SyncOperationKind`; derivations are device-local and never replicated — verified against `sync-contracts.ts:18-25` before implementation |
| T-11-SC | Tampering | npm/pip/cargo installs | accept | No packages installed in this plan |
