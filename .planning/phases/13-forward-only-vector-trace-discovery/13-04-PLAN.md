<objective>
Option D from `13-RESEARCH.md:298-311`, taken because it is orthogonal to every other option, makes all of
them cheaper, and benefits Phase 14 as well.

`SqliteStore.findNearestSummaries` pays two full loads before any arithmetic. The second one
(`sqlite-store.ts:1826-1828`) exists only to compute a retrievable-id set, and it does so with
`select payload from summaries where json_extract(payload,'$.personId') = ?` — visiting and JSON-parsing
all 145,765 rows, of which 89,059 are superseded and are returned only to be discarded in JS. Measured:
**7.04 s of query + 1.18 s of parse, and the bulk of the 1,296 MB resident** (`13-CONTEXT.md:44-50`).

The id-only, state-predicated form is exactly the column tuple of migration 3's
`idx_summaries_person_state (personId, state, id)` — the same trick migration 4 used to take
`listSummaryIdsMissingVector` from 4,090 ms to 45 ms.

**This is a hypothesis, not a measurement** (`13-RESEARCH.md` A1). The expression strings must match the
index's expressions character for character or SQLite silently declines the index — the exact ADR 0052 §2
`coalesce(...,'personal')` failure. So this plan does not claim the win; it *verifies* it, in two ways, and
records the outcome either way.

**No new index.** If migration 3's index does not cover the query, the correct response is to record that
finding and stop — NOT to add an index. `13-CONTEXT.md:177` and ADR 0054 `:155-165` are explicit: an added
index on these tables can silently steal `findNearestSummaries`' own vector query
(`idx_summary_vectors_provider_model_person`) or `listSummaryIdsMissingVector`'s
(`idx_summaries_state_id`), both of which return correct results either way and would simply have been slow
again, indefinitely. A phase that adds an index here without three query-plan assertions has re-run the
388× experiment.

Purpose: REQ-047; removes the dominant constant from every vector read this phase performs.
Output: the narrowed sweep, the R7 triple query-plan guard, and a measured before/after on a clone.
</objective>
