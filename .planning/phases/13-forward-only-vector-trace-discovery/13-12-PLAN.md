## Open Question 1, decided — retained but unreachable, not deleted

`13-RESEARCH.md:596-599` leaves it open and notes the string `trace_smith_pip_provider_bill` is a pinned
expectation in **four** tests across three suites, so whatever happens must handle all four in one pass —
leaving two green and two red is how a wave stalls.

**Decision D-13-5: `trace-candidate-core.ts` and `DeterministicTraceProposalPlanner` are retained and
unwired. `parallel-trace-backfill.ts` and `trace-backfill-worker.mjs` are deleted.**

- Retained, because CONTEXT forbids *tuning* the matcher and does not say delete; because deleting it would
  churn four tests across three suites for no behavioural gain; and because a tested-but-unreachable module
  is cheaper to reason about than a deletion whose blast radius includes `npm run hermes:smoke`.
- Unreachable, because a retained module with no fence is how it gets re-wired. Plan 13-01's structural test
  covers `src/daemon/`; this plan widens it to every production caller and adds deprecation headers naming
  GAP-12-E and this ADR.
- The parallel backfill goes, because its guiding comment is provably false on this corpus —
  `PARALLEL_TRACE_BACKFILL_THRESHOLD = 20_000` carries the assertion that the daemon's ongoing runs "stay
  well below this (a handful of new summaries per cycle)", and at 56,706 that is the false assumption the
  whole design rested on (`12-CLOSING.md:62-64`). Deletion is gated on `13-RESEARCH.md`'s assumption A2 —
  **re-verify with a grep before deleting**, and if a caller exists, keep the files and record the finding.

## The Hermes swap is CUT from Phase 13, and recorded as deferred (B6)

An earlier draft of this plan swapped `hermes:sleep`'s trace pass to `TraceDiscoveryRunner`. It is not
implementable as written and it is not worth forcing:

- `SleepOptionsSchema` is `{ databasePath, input }` and `HermesSleepRequestSchema` carries no person or
  scope field; `SleepReviewer` is constructed with no `writeStore` and `proposeTraces` is called with **no
  `personId`** (`sleep-command.ts:76-81`). `TraceDiscoveryRunnerOptions` requires `personId`, `provider`,
  `model`, and `allowedScopeIds`. An executor would improvise, and the plausible improvisation is a sentinel
  or a first-person lookup — the exact class of mistake T-10-05 and T-12-22 exist to prevent.
- It would create a **second writer to the Phase-13 checkpoint from a path holding no daemon lease**, which
  is the lost-update hazard Plan 13-11 refuses to create for itself.

Plan 13-01 already made the Hermes path boxes-only by injecting `NullTraceProposalPlanner` — permanently
for this phase, not as a holding action. So there is nothing to remove here and no test to churn. The
capability gap is recorded in `13-DEFERRED.md` and in ADR 0055's "not addressed here": threading
`personId`/`allowedScopeIds` through the Hermes request, and deciding whether that path is checkpoint
read-only (discovery runs, proposals are written, cursor and backlog untouched — the conservative choice
that matches "human-invoked, no contraction job") or takes the same lease check Plan 13-11 requires.
