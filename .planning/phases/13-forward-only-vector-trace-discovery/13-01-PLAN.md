<objective>
GAP-12-E. Make the daemon runnable unattended by taking the shared-term all-pairs trace pass out of its
path. Interim position is boxes-only.

**This is a holding action with an expiry date, not a fix.** `13-CONTEXT.md:133-138` forbids tuning,
thresholding, or otherwise rescuing the term matcher, and this plan touches none of its knobs:
`BROAD_TRACE_TERMS`, `NON_DISCRIMINATING_DOCUMENT_FLOOR`, `NON_DISCRIMINATING_DOCUMENT_FRACTION`,
`maxDocumentFrequencyFor`, `minimumTraceSummaries`, and `minimumConfidence` are all left exactly as they
are. The pass is not made better; it is made unreachable from the daemon.

**Switch location — decided deliberately, per `13-RESEARCH.md` Open Question 2.** The switch goes in
`ProposalScheduler`'s wiring, injected as `SleepReviewerOptions.tracePlanner`, NOT inside
`SleepReviewer.proposeTraces`. Consequences of that choice, all intended:

- `tests/sleep/sleep-reviewer.test.ts:186-207` (reviewer + default planner produces
  `trace_smith_pip_provider_bill`) stays green. The reviewer's own contract is unchanged.
- `tests/sleep/sleep-reviewer.test.ts:228-245` (an injected `tracePlanner` is used and its proposals are
  persisted) is the sanctioned seam this plan enters through — and it is the same seam Plan 13-10 will
  eventually leave permanently empty, because vector discovery is driven by the scheduler, not the reviewer.
- The Hermes path (`integrations/hermes/sleep-command.ts:76-81`) calls `reviewer.proposeTraces` directly
  and would otherwise be untouched — which on the live corpus means a human running `memory hermes:sleep`
  detonates the 18-minute all-pairs pass by hand. Task 2 closes that with **the same one-line remedy**:
  inject `NullTraceProposalPlanner`. An earlier draft of this plan used a corpus-size refusal guard
  instead; it is withdrawn, for three reasons the plan check named and I accept. (1) It had no cheap
  input — `MemoryStore` has no summary-count method, so its own fallback was a 56,706-row
  `listSummaries` load added to the very path it was protecting from a corpus-scale operation.
  (2) It added a public `HermesSleepResult` field that a later plan then deleted. (3) A constant named
  after the matcher's blow-up curve reads as the tuning knob CONTEXT forbids, whatever its docstring
  says. The null planner has none of those properties and needs no removal later.

**Disposition of the four pinned `trace_smith_pip_provider_bill` expectations — decided here, in one
pass**, as `13-RESEARCH.md:477` requires. Three stay green **unedited**, because they construct the
planner or the reviewer directly and neither is being changed:
`tests/traces/trace-proposal-planner.test.ts:72-76`, `:79-105`, and
`tests/sleep/sleep-reviewer.test.ts:186-207`. Two **change in this plan**, because the Hermes path stops
producing trace proposals: `tests/integrations/hermes-sleep-command.test.ts:177`/`:208` and
`tests/integrations/hermes-smoke-harness.test.ts:52`. Both changes are made here, in wave 1, with an
inline comment naming GAP-12-E and ADR 0055 — not deferred to a later plan, because leaving two red is
how a wave stalls.

**Landing this first is what makes the daemon runnable**, so waves 2-8 can be planned and measured against
a daemon that actually runs. The daemon stays stopped and the LaunchAgent stays unloaded until this plan
is merged (`13-CONTEXT.md:188`, `13-RESEARCH.md:489`).

Purpose: GAP-12-E; unblocks REQ-046's replacement work.
Output: an injected null planner, the scheduler wiring, the Hermes refusal guard, and two behaviour fences.
</objective>
