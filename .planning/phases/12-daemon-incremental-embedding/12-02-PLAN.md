<objective>
Close GAP-12-B and make `memory status` truthful.

`listSummaryIdsMissingVector` (`sqlite-store.ts:1692-1704`) selects `from summaries` with no state
predicate. On the live corpus that is 138,373 rows — 49,314 `compacted` plus 89,059 `superseded` — and the
superseded ones are rows `findNearestSummaries` deliberately filters out (`sqlite-store.ts:1719-1727`) and
`rebuild-derivations` tombstones (`rebuild-derivations-command.ts:167-175`). Embedding them is ≈36 wasted
minutes and ~137 MB of vectors that vector search will never return.

**Locked decision 3 in `12-CONTEXT.md`: add the state predicate; do NOT run `memory prune-superseded`.**
The rows stay, per ADR 0050's supersede-not-delete auditability. This plan changes what counts as a
backfill candidate, not what exists.

**The predicate alone would make the query 11× slower, and the index is not optional.** Measured
read-only against the live corpus, then on a `cp -c` clone (F3):

| query | rows | wall clock |
|---|---:|---|
| today, no predicate | 138,373 | 329 ms |
| predicate, no index | 49,314 | **4,090 ms** |
| predicate + expression index | 49,314 | **45 ms** |

`explain query plan` explains it exactly. Today's query is `SCAN summaries USING COVERING INDEX` — id-only,
so it never touches `payload`. Adding `json_extract(payload,'$.state')` degrades it to a plain index scan
that must read `payload` for all 138,373 rows out of a 5.0 GB table. The expression index restores covering
behavior: `SEARCH summaries USING COVERING INDEX idx_summaries_state_id (<expr>=?)`. Index build cost is
1.16 s on the full corpus, and the result is **7× faster than the query in production today** — so this
makes `memory status` and Plan 12-04's repair pass cheaper than they are now, not merely no worse.

Without the index, Plan 12-04's repair pass would add a ~4 s full-payload scan every tick forever,
including in steady state with nothing missing. That is the opposite of "bounded by the number of new
summaries."

This is a cost of implementing Locked decision 3 correctly, not an argument against it. The remedy is the
index, not a prune.

This plan also adds `listSummariesByIds`, the bounded by-id fetch Plan 12-04's repair pass needs. There is
no `getSummary(id)` on `MemoryStore` today (verified), and the alternative — reusing the backfill's full
`listSummaries()` — is the per-tick full-parse anti-pattern the phase exists to avoid.

**CLAUDE.md is explicit and this plan is where it bites: `sqlite-store.ts` and `in-memory-store.ts` both
implement `MemoryStore` in full, so every behavior here lands in BOTH.** A predicate in one store only is
the parity break Phase 8 spent a gap-closure plan on.

Purpose: REQ-043 (bounded incremental cost), REQ-045 (a truthful completeness surface).
Output: a missing-set query that means "embeddable" and is index-covered, a `limit` so callers need not
materialize it, a status denominator that agrees with it, and a bounded by-id fetch.
</objective>
