<objective>
Close GAP-12-B and make `memory status` truthful.

`listSummaryIdsMissingVector` (`sqlite-store.ts:1692-1704`) selects `from summaries` with no state
predicate. On the live corpus that is 138,373 rows — 49,314 `compacted` plus 89,059 `superseded` — and the
superseded ones are rows `findNearestSummaries` deliberately filters out (`sqlite-store.ts:1719-1727`) and
`rebuild-derivations` tombstones (`rebuild-derivations-command.ts:167-175`). Embedding them is ≈36 wasted
minutes and ~137 MB of vectors that vector search will never return.

**Locked decision 3 in `12-CONTEXT.md`: add the state predicate; do NOT run `memory prune-superseded`.**
The rows stay, per ADR 0050's supersede-not-delete auditability. This plan changes what counts as a
backfill candidate, not what exists.

This plan also adds `listSummariesByIds`, the bounded by-id fetch Plan 12-04's repair pass needs. There is
no `getSummary(id)` on `MemoryStore` today (verified), and the alternative — reusing the backfill's full
`listSummaries()` — is the per-tick full-parse anti-pattern the phase exists to avoid.

**CLAUDE.md is explicit and this plan is where it bites: `sqlite-store.ts` and `in-memory-store.ts` both
implement `MemoryStore` in full, so every behavior here lands in BOTH.** A predicate in one store only is
the parity break Phase 8 spent a gap-closure plan on.

Purpose: REQ-043 (bounded incremental cost), REQ-045 (a truthful completeness surface).
Output: a missing-set query that means "embeddable", a status denominator that agrees with it, and a
bounded by-id fetch.
</objective>
