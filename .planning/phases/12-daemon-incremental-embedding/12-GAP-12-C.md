# GAP-12-C — `vendorModel` cannot produce the layout it verifies, and fetches 4 of 5 files

**Status:** open — blocks Plan 12-05 Task 3, and therefore the whole backfill chain
**Found:** 2026-07-29 by the Plan 12-05 executor, running the real command
**Verified independently by the orchestrator** in source and against the on-disk cache, 2026-07-29

`memory embeddings --action enable` is the only CLI path that touches the network, and it is broken in
shipped code. Two deterministic defects that must be fixed together — fixing either alone turns one
`ENOENT` into another.

## Defect 1 — the write path and the read path are different places

`src/embeddings/model-vendor.ts`:

| line | what it does |
|---|---|
| 51 | `env.localModelPath = localModelPath` — where local models are **read from** |
| 56 | `await pipeline("feature-extraction", repo, …)` — downloads land in `env.cacheDir` |
| 76 | `verifyManifest` reads `${localModelPath}/${repo}/${relPath}` — **flat** |

`env.cacheDir` is still defaulted to `node_modules/@huggingface/transformers/.cache`, and its layout is
**revision-nested**, not flat. Confirmed on disk:

```
ea104dacec62c0de699686887e3f920caeb4f3e3/config.json
ea104dacec62c0de699686887e3f920caeb4f3e3/onnx/model.onnx
ea104dacec62c0de699686887e3f920caeb4f3e3/tokenizer_config.json
ea104dacec62c0de699686887e3f920caeb4f3e3/tokenizer.json
```

Nothing ever writes the flat path `verifyManifest` reads. **Repointing `cacheDir` at the target does not
fix this** — the layouts differ, so the copy/flatten step has to be explicit.

## Defect 2 — one manifest file is never fetched at all

`BGE_SMALL_EN_V1_5_MANIFEST` pins **five** files. `pipeline("feature-extraction", …)` requests four.
**`special_tokens_map.json` is absent from the cache entirely** — it is not a layout problem, the file was
never downloaded. Verified by listing the cache above.

The other four hash **exactly** to their pinned manifest values, and the gitignored fixture at
`tests/fixtures/models` holds all five correctly. **The manifest is right; the code meant to reproduce it
is not.**

## Why it shipped — the third instance of one meta-pattern

`tests/embeddings/model-vendor.test.ts:36` is `describe.runIf(RUN_NETWORK_TESTS)`, gated on
`MEMORY_RUN_NETWORK_TESTS === "1"`. Its **first case is "writes the pinned fp32 file set under
localModelPath"** — precisely the assertion that fails. Those are the **4 skipped tests** in the
otherwise-green 1,106-passed suite. The golden tests pass because they read the hand-assembled fixture,
never the vendored output.

This is the third time in two phases that the test which would have caught a defect did not run:

| gap | why the test did not catch it |
|---|---|
| GAP-11-G | two existing tests actively pinned the **pre-reversal** rule — green while encoding the defect |
| GAP-12-A | every backfill fixture hardcoded the ONE embedder whose class and emitted `model` coincide |
| **GAP-12-C** | the test asserts exactly the failing behavior but is **skipped by default** |

A skipped test is not weaker coverage than a missing one — it is worse, because the suite reports a
number that implies the path is covered.

## Fix direction

Fetch the five pinned files directly from `https://huggingface.co/{repo}/resolve/{revision}/{file}` into
the flat layout `verifyManifest` already expects, then verify. This addresses both defects, pins the
revision explicitly rather than relying on library cache semantics, and is the most auditable shape for
the one path in the product that reaches the network.

Prove the load separately with `probeEmbedderHealth` after vendoring, which covers "the model actually
works" better than `pipeline()` did as a side effect of fetching.

**The test must run in the default suite.** Serve the five fixture files over a loopback HTTP server and
point the fetch at it — that exercises the real fetch, flatten, and verify logic offline and
deterministically, satisfying REQ-040/REQ-044. Keep a network-gated case for the real Hub, but the
layout and coverage logic must no longer depend on a test nobody runs.
