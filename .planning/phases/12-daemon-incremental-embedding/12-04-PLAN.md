<objective>
Plan 12-03's post-commit stage has exactly one hole: a crash between `commitContractionSlice` returning
and `saveSummaryVectors` completing, or a transient embedder failure, leaves a summary with no vector. That
state is recoverable and detectable — this plan makes the daemon actually recover it, so an operator does
not have to notice `missingVectors > 0` in `memory status` and hand-run a backfill.

**The budget is the whole design.** An unbounded missing-set pass re-reads the corpus and is precisely the
SC2 violation the phase forbids, and `ProposalScheduler.createStagingStore`
(`proposal-scheduler.ts:83-103`) is the named-in-CONTEXT anti-pattern for how this goes wrong: it loads and
re-parses every summary, box, anchor, proposal, and trace for the person, every cycle. Do not copy it.

Three constraints, all from `12-RESEARCH.md`, all now satisfiable because their prerequisites landed:
1. The pass could not run at all before GAP-12-A was fixed — it would have returned the whole corpus every
   tick (Plan 12-01).
2. It must not use the backfill's `listSummaries()` full load — it uses `listSummariesByIds` (Plan 12-02).
3. It must not chase superseded rows — the state predicate handles that (Plan 12-02).

Purpose: REQ-043; ROADMAP SC1 (crash path) and SC2 (bounded cost).
Output: a rate-limited, budgeted repair pass wired as an optional, failure-swallowing daemon dependency.
</objective>

  <behavior>
    - 500 summaries missing vectors, budget K=200 → exactly 200 embed calls and 200 rows written in one
      invocation; a second invocation writes the next 200; a third writes the last 100
    - Ordering is stable and forward-progressing: successive invocations must not re-serve the same ids.
      Since `listSummaryIdsMissingVector` is ascending-by-id and each pass removes what it embeds, taking
      the first K each time converges. Assert convergence to zero, not just the per-pass cap.
    - Crash-hole healing: drive a real contraction slice with `faults.reach("after_contraction_checkpoint")`
      throwing, so the summary is committed and the vector is not; assert the summary exists with no
      vector, then run the repair pass and assert the vector now exists
    - Zero missing → zero embed calls, zero store writes, and the pass returns promptly
    - A throwing embedder, a throwing store write, and a throwing query each leave `runDue` returning
      normally with the failure counted — `runDue` NEVER throws
    - Rate limiting: two `runDue` calls inside the minimum interval perform work at most once; the third,
      after the injected clock advances past the interval, works again
    - A superseded summary with no vector is never embedded (inherited from the store predicate — assert
      it here anyway, at this layer, because this is the layer that would silently re-embed 89,059 rows)
  </behavior>
  <action>
    Create `src/daemon/embedding-repair.ts` exporting `EmbeddingRepairRunner` with a
    `runDue(): Promise<EmbeddingRepairResult>` method, constructed with `{ store, embedder, clock,
    budget?, minimumIntervalMs? }`. Defaults: `budget = 200`, `minimumIntervalMs = 15 * 60 * 1000`.

    `runDue`:
      if `clock.monotonicNow()` (or the injected clock's equivalent — match the `ContractionClock` shape
        already used in this directory) is before `nextDueAt`, return a skipped result immediately
      ids = `await store.listSummaryIdsMissingVector(embedder.provider, embedder.model)`
      take the first `budget` ids
      summaries = `await store.listSummariesByIds(thoseIds)`   — NEVER `listSummaries()`
      embed each with `embedder.embed(summary.summaryText)` (passage mode; never `embedQuery`)
      skip-and-count any summary with a falsy `personId`; never substitute a sentinel (T-10-05)
      one `await store.saveSummaryVectors(records)` for the batch
      set `nextDueAt`, return `{ skipped, examined, persisted, failed, remaining }`

    Wrap the whole body in try/catch. `runDue` returns a result on every path and throws on none. Log
    counts, provider, and model only — never summary text or ids-with-text.

    The clock must be injected (repo determinism invariant); no `Date.now()` and no `performance.now()`
    inside this module.

    `remaining` is `ids.length - persisted` from the ids the pass actually saw — it is an observation for
    the operator, not a second query. Do not issue a second `listSummaryIdsMissingVector` to compute it.
