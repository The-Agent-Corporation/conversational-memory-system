<objective>
Close GAP-12-C: `memory embeddings --action enable` cannot succeed, because `vendorModel` writes to one
place and verifies another, and never fetches one of the five pinned files.

Both defects verified in source and against the on-disk cache (see `12-GAP-12-C.md`):

1. `model-vendor.ts:51` sets `env.localModelPath`; `pipeline()` at `:56` downloads to `env.cacheDir` in a
   **revision-nested** layout; `verifyManifest` at `:76` reads a **flat**
   `${localModelPath}/${repo}/${relPath}`. Nothing writes what it reads.
2. `pipeline("feature-extraction", …)` requests four files. `special_tokens_map.json` is **never fetched**.

**The more important half of this plan is the test.** The existing case at
`tests/embeddings/model-vendor.test.ts:36` asserts *precisely* the failing behavior — "writes the pinned
fp32 file set under localModelPath" — but sits behind `describe.runIf(RUN_NETWORK_TESTS)`. Those are the
**4 skipped tests** in the otherwise-green 1,106-passed suite. This is the third defect in two phases that
a test would have caught but didn't run (see the table in `12-GAP-12-C.md`). Fixing the code without
fixing the coverage leaves the same blind spot for the next change.

**Verified precondition for the test design:** all five files under
`tests/fixtures/models/Xenova/bge-small-en-v1.5` hash **exactly** to the pinned manifest values
(orchestrator, 2026-07-29). A loopback server can therefore serve them and real verification will pass —
the offline test exercises genuine fetch/flatten/verify logic, not a mock of it.

Purpose: REQ-044.
Output: a working vendor path, and a test that runs every time anyone types `npm test`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| the network → the local model directory | The only path in the product that fetches remote bytes |
| vendor success → `enabled: true` | `embeddings-command.ts` trusts `vendorModel`'s resolution completely |
| manifest → integrity | The pinned hashes are the sole defense against a substituted model |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12-30 | Tampering | A partial vendor leaving plausible files a later run accepts | mitigate | Atomic staging; post-failure assertion that nothing survives verification |
| T-12-31 | Tampering | Editing the manifest to match whatever was downloaded | mitigate | Manifest asserted byte-unchanged; the fixture already proves the hashes are correct |
| T-12-32 | Spoofing | Fetching from an unpinned revision or a redirected host | mitigate | Revision pinned in the URL; per-file sha256 verified before use |
| T-12-33 | Repudiation | Shipping the fix with coverage that still does not run | mitigate | Task 1's test carries no flag gate; the summary must state whether the fixture was present |
| T-12-34 | Information Disclosure | A test that silently reaches the public internet | mitigate | Offline test points at loopback only; real-Hub cases stay behind the existing flag |
| T-12-SC | Tampering | npm/pip/cargo installs | accept | No packages installed; `node:http` and `fetch` are built in |
</threat_model>
