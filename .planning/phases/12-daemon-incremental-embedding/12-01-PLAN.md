<objective>
Close GAP-12-A: make the embedder's advertised model identity and its emitted model identity the same
string, so the backfill's query key and its write key agree and the missing set actually shrinks.

This is Locked decision 4 in `12-CONTEXT.md`: the identity is fixed BEFORE any backfill runs. A backfill
on the broken identity cannot resume, cannot be verified complete, and reports
`missingVectors == totalSummaries` forever.

**The chosen fix shape is (a) from the research, done properly.** `TransformerEmbedder.model` becomes the
composed `repo@revision` string, and the composition lives in ONE exported function that every surface
calls. Rejected: (b), a `revision` column plus schema v4 — it widens the `MemoryStore` interface and
`SummaryVectorRecord`, ripples through both stores, `Embedding`, and every vector call site, and it does
not by itself prevent the bug class (a caller can still pass the wrong model to the query). Rejected:
(c), keying on a probe embed's result — leaves the identity implicit, which is the defect.

Choosing (a) also fixes a second, unreported instance of the same two-key bug for free:
`src/retrieval/memory-retriever.ts:585` compares a stored `memoryEmbedding.model` against
`options.embedder.model`, which under `TransformerEmbedder` could never match. Do not edit that file —
verify it now behaves, and say so in the summary.

REQ-045 requires provider/model/**version** be recorded so stale-model vectors are detectable. The
composed string keeps the pinned revision inside the persisted identity, so SC4 remains satisfiable.

Purpose: REQ-045; unblocks Locked decisions 1 and 2.
Output: one canonical identity, a regression test over an embedder whose two identities deliberately
differ, and a backfill that resumes.
</objective>
