<objective>
Give the daemon an embedding path. It has none today: `saveSummaryVectors` has exactly one caller,
`backfill-embeddings-command.ts:111`.

**Seam: a post-commit stage inside `ContractionRunner.drainSlice`, driven by the summaries the slice just
wrote.** Cost is `summaries.length` with zero queries, so SC2 holds by construction rather than by a scan
budget. The shape already exists in this repo — `rebuild-derivations-command.ts:167-175` post-commit
tombstones vectors from `slice.supersessions`; this is the symmetric write.

**Take BOTH halves of that precedent, not just the write (F6).** An earlier draft of this plan added the
write and omitted the delete. Correctness would have survived — `findNearestSummaries`' GAP-11-A sweep
drops vectors whose summary is non-retrievable — but stale vector rows would accumulate unboundedly and,
after Plan 12-02's state predicate, be unreachable by the missing-set query that is now the only thing that
could find them. `slice.supersessions` is already in scope at that point and `deleteSummaryVectors` already
exists. The daemon does what `rebuild-derivations` does.

The decisive argument is upsert. A continuing topic's trailing active span is re-emitted every slice under
the *same* deterministic id (`summaryId(personId, firstEventId, topicLabel)`, `contraction-runner.ts:593`)
with *changed* text — documented at `contraction-runner.ts:276-277`. A missing-set-driven scheduler would
never see it (the row exists) and its vector would go stale permanently. Embedding the set the slice
handed to `commitContractionSlice` upserts it for free.

**Departure from the research, stated deliberately.** `12-RESEARCH.md` recommends this stage live in the
daemon's contraction work item (`daemon.ts:136-149`). It goes inside `ContractionRunner.drainSlice`
instead, one boundary lower. Three reasons: (1) `DaemonLoopDependencies.contractionRunner` is a deliberately
narrow structural type returning `Promise<{complete?: boolean} | unknown>` (`daemon.ts:31-33`) — putting
the stage above it means widening that seam to carry `Summary[]` out to a caller that has no other use for
it; (2) failure isolation is one try/catch in one function rather than a rule the daemon must remember;
(3) `daemon.ts:145-148` maps any contraction throw to `storage_failure`, so keeping the stage below that
line makes it structurally impossible for an embedder fault to be reported as a storage fault. The
research's own rejection of Option A (inside the transaction) and Option C (a separate scheduler) stands
unchanged and is not revisited.

Rejected alternatives, both from the research and both still rejected: inside the commit transaction
(couples memory formation to embedder health — a corrupt ONNX file would stop the daemon forming
summaries), and a separate scheduler (needs a per-tick corpus query and cannot see upserts).

Purpose: REQ-043, REQ-045; ROADMAP SC1, SC2, SC3.
Output: the embed stage, its wiring, the SC3 negative test, and ADR 0052.
