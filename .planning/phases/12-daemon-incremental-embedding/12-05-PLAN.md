milestone.

**One more ordering constraint, added after the plan check (F3).** Migrations run inside the `SqliteStore`
constructor whenever `readOnly` is false (`sqlite-store.ts:195-198`), so **any `memory` command that opens
the live database is a schema write** — and Plan 12-02 adds a v4 index migration. The first open by this
build must therefore come AFTER the `pre-phase12` backup exists, not before. Task 1 stops the daemon at the
process level precisely so it can do that without opening the database.

**Ordering is not arbitrary and every alternative produces a broken store.** Backfilling before enabling
writes 49k rows keyed `("deterministic","keyword-hash-v1")` that the ONNX missing set cannot see and
`findNearestSummaries` filters out — ~76 MB of dead rows with no cleanup path. Restarting the daemon
before the backfill completes gives new summaries ONNX vectors while the corpus has none, so retrieval
ranks over a ~0.1% sample. **The daemon stays stopped from this plan through Plan 12-07.**
