<objective>
Extend the `memory status` operator surface (`MemoryStatusCommandResult`) with a live `embeddingBackfill`
completeness snapshot: `{ provider, model, totalSummaries, missingVectors, completedFraction }`, computed
by a cheap live query — no new persisted state.

Purpose: Satisfies REQ-042 SC4's point-in-time half — anyone NOT watching a running backfill process can
still ask "is the corpus caught up?" and get a ground-truth answer that can never drift from the actual
`summary_vectors` table (Plan 03 delivers the live-stdout half). Because it re-queries the same missing-set
the backfill drives off, it is always exactly consistent with real state.
Output: `EmbeddingBackfillSnapshot` type + `embeddingBackfill` field wired into the existing status
`Promise.all`, plus status tests.
</objective>

From src/embeddings/embedder-resolver.ts (probeEmbedderHealth NEVER throws — use it, not resolveEmbedder):
```typescript
export interface EmbedderHealth {
  enabled: boolean;
  provider: string;   // when disabled: the config-default aspirational provider ("onnx-transformers")
  model: string;      // when disabled: the config-default aspirational model ("Xenova/bge-small-en-v1.5")
  revision: string;
  healthy: boolean;
  reason: string | null;
}
export async function probeEmbedderHealth(databasePath: string): Promise<EmbedderHealth>;
```

CRITICAL identity nuance (verified against embedder-resolver.ts + embeddings-config.ts + embedder.ts):
When the embedder is DISABLED (default), `resolveEmbedder` returns `DeterministicEmbedder`
(provider `"deterministic"`, model `"keyword-hash-v1"`) — but `probeEmbedderHealth` reports the config's
aspirational defaults (`"onnx-transformers"` / `"Xenova/bge-small-en-v1.5"`). The backfill writes under the
DeterministicEmbedder identity. So the snapshot's (provider, model) MUST be derived to match what backfill
actually writes: use `"deterministic"`/`"keyword-hash-v1"` when `!health.enabled`, else `health.provider`/`health.model`.
