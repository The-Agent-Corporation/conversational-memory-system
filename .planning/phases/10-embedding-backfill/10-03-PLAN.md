<objective>
Build the `memory backfill-embeddings` CLI command: resolve the active embedder once, query the missing-set
resume key, load summaries into an id→Summary map, then embed each missing summary's `summaryText` and
persist vectors in ~500-record transactional batches (via Plan 01's `saveSummaryVectors`), emitting one JSON
progress line per batch.

Purpose: This is REQ-042's core deliverable. SC1 (zero missing after a full run), SC2 (kill+restart resumes
cleanly), and SC3 (idempotent second run) all fall out of the missing-set-as-checkpoint pattern plus
per-batch transactions — no separate checkpoint table. SC4's live-stdout half ships here (the point-in-time
half is Plan 02's `memory status` field). This plan delivers the command + tests at seeded scale; the
full-corpus live-DB run is a manual verification (10-VALIDATION.md), NOT a task here.
Output: New command module + registry entry + SC1-SC4 integration tests.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator CLI process → embedder | The command resolves and uses the active embedder; must not silently mix providers |
| embedder output → summary_vectors | Vectors tagged with person/scope; mis-tagging causes cross-scope leakage |
| running process → SIGKILL | A kill mid-run must never corrupt the vector set or duplicate work |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-05 | Information Disclosure | Cross-scope vector leakage via mis-tagged personId/scopeIds | mitigate | Each record's `personId`/`scopeIds` sourced ONLY from its own `Summary`; a summary lacking `personId` fails loud (never tagged a catch-all sentinel). Per-person fixture test asserts correct tagging. |
| T-10-08 | Tampering (data integrity) | Silent write under wrong (provider, model) after a mid-run config change | mitigate | `resolveEmbedder` called once; its instance's `provider`/`model` used for the missing-set query AND every write — never re-resolved mid-loop, never a hardcoded string. |
| T-10-09 | Tampering / silent data loss | catch-and-continue swallowing an embed() failure, or silent fallback to DeterministicEmbedder | mitigate | No per-item try/catch-and-continue; `embed()`/`resolveEmbedder` throws propagate to `process.exitCode = 1`. "Completed but missing-set non-empty" is the warning sign the tests guard against (SC1). |
| T-10-10 | Tampering | Partial batch committed on SIGKILL mid-batch | mitigate | Writes go through Plan 01's transactional `saveSummaryVectors` (all-or-nothing per batch); on restart `listSummaryIdsMissingVector` re-derives the true remaining set (SC2 test). |
| T-10-SC | Tampering | npm/pip/cargo installs | accept | No new packages introduced (RESEARCH: composition of existing Phase 7-9 modules only). |
</threat_model>
