<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| relay account → enrollment | Service access alone must not authorize a device or unwrap keys. |
| approving/recovery credential → membership CAS | A one-time exact transcript changes the trusted device set and future key epoch. |
| local sync client → relay HTTP server | Bearer credentials, opaque envelopes, timeouts, and ambiguous network outcomes cross the production transport. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-20 | Spoofing | Enrollment request | critical | mitigate | Full-transcript shared-secret code, active signature, exact device-name display, expiry, and consume-before-result. |
| T-06-21 | Elevation of privilege | Recovery enrollment | critical | mitigate | Require both verified account and current recovery proof; passphrase unwrap remains local. |
| T-06-22 | Tampering | Revocation/key rotation | critical | mitigate | Exact control CAS and independently random next epoch packaged only to remaining members. |
| T-06-23 | Information disclosure | Recovery errors/packages | high | mitigate | Opaque packages, Argon2id local unwrap, uniform failure, and no support bypass. |
| T-06-34 | Spoofing / Tampering / Information disclosure | HttpSyncRelay | high | mitigate | HTTPS requirement, strict versioned request/response schemas, exact bearer-header propagation/redaction, bounded deadlines/bytes, and lost-response reconciliation. |
</threat_model>
